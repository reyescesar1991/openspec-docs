Proposal: Frontend Screen Analysis — Bookia SaaS ​

Intent ​

Define a complete frontend screen inventory from Bookia's ~30-table data model. The project is a blank React 19 + Vite JS canvas (Supabase Auth only). This analysis bridges data model → screens, enabling a future Angular frontend implementation, UI/UX component planning, and effort estimation.

Scope ​

In Scope ​

  • 71 screens derived from ~30 tables across 11 domains
  • CRUD analysis per screen (Create/Read/Update/Delete/List/specialized)
  • Permission mapping: SystemMenu transaction codes → OrganizationRoleMenu read/write/delete → PlanMenu subscription gating
  • Navigation tree mirroring SystemMenu hierarchy
  • CRM privacy fallback patterns (local field → global field for emails/phones)
  • Calendar availability engine constraints and real-time requirements

Out of Scope ​

  • No code generation, routing, UI library, or test framework decisions
  • No DB migrations or backend changes
  • No migration specs for existing data

Capabilities ​

New Capabilities ​

Each domain becomes a discrete spec in the Specs phase:

  • auth-onboarding: Login, Signup, Tenant Wizard, Tenant Switcher
  • system-config: Exchange Rates, Document Types, Payment Methods, Plans, Plan-Menu Assignment
  • org-config: Org Profile, Payment Methods, Roles, Permissions Matrix, Currency History, Expense Categories, Expenses
  • user-profile: Profile, Preferences
  • crm: Client Search (global), Client Profile (global), CRM List (tenant), CRM Contact Detail, Client Records
  • hr: Employee Search (global), Employee Profile (global), Staff Directory, Contract Detail, Attendance Dashboard
  • services-catalog: Service Catalog, Resource Inventory, Service-Resource Mapping, Employee Skills, Commission Overrides
  • scheduling: Employee Working Hours, Employee Time Off, Resource Hours, Resource Time Off, Conflict Dashboard
  • queue: Queue Config, Kiosk/Totem, Queue Board Display, Queue Reception Control
  • appointments: Booking Calendar, New Appointment, Appointment Detail/Edit, Today's Agenda, Client Booking Widget
  • financial: Payment/Checkout, Payment History, Commission Registry, Commission Payout, Commission Dashboard
  • reviews: Review Submission, Review Dashboard
  • reports: Executive Dashboard, Appointment Analytics, Financial P&L

Modified Capabilities ​

None — no existing specs to modify.

Approach ​

  1. Derive screens in topological order: master tables → tenant config → global identities → identity-tenant relations → resources/services → scheduling → queues → transactions
  2. Map each screen to SystemMenu transaction codes (CFG-*, CRM-*, HRM-*, SER-*, SCH-*, QUE-*, FIN-*, REP-*) and OrganizationRoleMenu permission checkboxes
  3. Define nav tree from SystemMenu parent-child hierarchy, filtered by PlanMenu → OrganizationRoleMenu
  4. Document cross-cutting patterns: tenant switching middleware, CRM privacy fallback, real-time subscriptions, calendar availability, kiosk isolation

Key Architectural Decisions to Validate ​

  1. Navigation tree — SystemMenu → filtered by PlanMenu → OrganizationRoleMenu per user role
  2. Calendar availability — Edge Function vs DB function for multi-constraint slot computation
  3. Kiosk route — separate /kiosk with touch-optimized layout, no sidebar
  4. CRM privacy fallback — local field → global field display logic for email/phone
  5. Real-time — Supabase Realtime for Queue Board and Booking Calendar
  6. Tenant switching — app.current_tenant_id + app.current_user_role_id middleware
