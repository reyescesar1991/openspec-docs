Design: Generic Table Column Enhancement ​

Technical Approach ​

Backward-compatible extension to TableColumn that adds 4 optional props controlling rendering, interaction, and filtering. The component uses ngOnChanges as the single coordination point: it rebuilds displayedColumns (visibility filter) and the filterPredicate whenever columns change. Template binds conditionally — [matTooltip], (click), [style.cursor] — only when the corresponding column prop is truthy. MatTooltipModule is already available via MaterialModule → SharedModule; no new imports needed.

Data Flow ​

Parent component
  │
  ├─ @Input columns: TableColumn[]  (with optional visible/tooltip/clickeable/filterable)
  │
  ▼
ngOnChanges(changes)
  ├─ displayedColumns = columns.filter(c => c.visible !== false).map(c => c.key)
  └─ dataSource.filterPredicate = (data, filter) =>
       columns.some(col =>
         col.filterable !== false &&
         String(data[col.key]).toLowerCase().includes(filter)
       )
  │
  ▼
Template rendering
  ├─ *matHeaderRowDef="displayedColumns"  ← only visible columns
  └─ <td [matTooltip]="col.tooltip"       ← only when col.tooltip truthy
           (click)="col.clickeable && cellClick.emit({column: col, row: element})"
           [style.cursor]="col.clickeable ? 'pointer' : null">
         {{ element[col.key] }}
     </td>
  │
  ▼
User interaction
  ├─ Types in filter → applyFilter() → dataSource.filter = value → custom predicate
  └─ Clicks cell → cellClick.emit({ column, row }) → parent handles

Interfaces / Contracts ​

typescript
// tableColumn.interface.ts
export interface TableColumn {
  key: string;
  header: string;
  visible?: boolean;     // default true when undefined
  tooltip?: string;      // matTooltip text; no tooltip when undefined/empty
  clickeable?: boolean;  // emits cellClick when true
  filterable?: boolean;  // included in global search when not false
}

// Event emitted on cell click
cellClick: EventEmitter<{ column: TableColumn; row: any }>

Migration / Rollout ​

No migration required. All new properties are optional (?:). Existing column configs without them work identically — visible defaults to rendered, filterable defaults to searchable, no tooltips, no click events.
