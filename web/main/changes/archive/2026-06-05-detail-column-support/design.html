Design: Detail Column Support ​

Technical Approach ​

Extend TableColumn with optional detail/detailFrom properties for invisible data carriage. On cellClick, the generic table iterates its own columns, collects detail: true field values from the clicked row, and emits them as detailData in an extended event payload. The parent component refactors from hardcoded data to a dynamic API call, maps response fields to TableColumn[], opens a ConfirmationDialog on click, and adds a date filter with search button. The change is fully backward-compatible since new interface properties are optional and the extended payload adds a field without removing any.

Architecture Decisions ​

OptionTradeoffDecision
Payload shape: extend vs. new emitterExtend is simpler (no new output), but widening the type could cause TS strict errors in consumers that destructure the full type. Existing consumers only destructure {column, row} — adding an optional field won't break them.Extend cellClick type to { column, row, detailData? }
Detail collection: component vs. parentParent-side iteration couples every consumer to detail logic. Component-side keeps it DRY — the generic table already knows its columns and the clicked row.Component collects — emitCellClick iterates this.columns, filters detail: true, maps to {label: header, value: row[key]}
API data fetch: subscribe vs. async pipeAsync pipe is reactive but breaks the existing error-handling pattern (subscribe with next/error). The project consistently uses subscribe for imperative data fetching (ApiGateway.execute returns Observable).subscribe() with next/error callbacks, matching project convention
Modal invocation: fire-and-forget vs. handle afterClosedUser explicitly said NOT to subscribe to afterClosed. ConfirmationDialogService.open() returns Observable<any> from afterClosed() — calling it without subscribing is valid Angular; the dialog lifecycle is managed by MatDialog internally.Fire-and-forget — call .open() without .subscribe()

Data Flow ​

Parent Component (tabla-consulta-ordenes-subasta)
  │
  │ ngOnInit() / search click
  │   │
  │   ▼
  │ getOpenOperationsCurrencyData({ executionTime, market: '' })
  │   │
  │   ▼
  │ subscribe(
  │   next: response → map response.data() to TableColumn[] + rows
  │   error: → ModalSweetalert2Service.error()
  │ )
  │
  │ cellClick($event)
  │   │
  │   ├──→ ConfirmationDialogService.open('title', $event.detailData)
  │   │
  │   └── (no afterClosed subscription)
  │
  ▼
GenericTableWithoutActionsComponent
  │
  │ emitCellClick(column, row)
  │   ├── if !clickeable → return
  │   ├── collect detailData = columns.filter(detail)
  │   │     .map(c => ({ label: c.header, value: row[c.key] }))
  │   └── emit cellClick({ column, row, detailData })

Interfaces / Contracts ​

typescript
// tableColumn.interface.ts — extended
export interface TableColumn {
  key: string;
  header: string;
  visible?: boolean;
  tooltip?: string;
  clickeable?: boolean;
  filterable?: boolean;
  detail?: boolean;       // NEW — marks column as invisible data carrier
  detailFrom?: string;    // NEW — reserved for future cross-column lookup
}

// generic-table-without-actions.component.ts — widened payload
@Output() cellClick = new EventEmitter<{
  column: TableColumn;
  row: any;
  detailData?: { label: string; value: any }[];
}>();

// Expected API response shape (from getOpenOperationsCurrencyData):
// {
//   columns: Array<{ key: string; header: string; visible?: boolean; detail?: boolean }>,
//   rows: Array<Record<string, any>>
// }

Migration / Rollout ​

No migration required. All new interface properties are optional. The parent component's refactor is self-contained within the change — no other consumer needs updating.
